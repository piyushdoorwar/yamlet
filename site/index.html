Get started

One container. Your folder. Your browser.

Yamlet ships as a single container image. Mount the folder you want to keep your collections in, and the app reads and writes YAML there directly.

Start Yamlet in your workspace folder

Run this from the directory that holds (or will hold) your collections. It is mounted at /workspace and bound to your machine only. The yamlet-data volume keeps private app state, such as the Chrome extension pairing, across updates.

$ docker run -d --pull always --name yamlet -p 127.0.0.1:7878:7878 -v .:/workspace -v yamlet-data:/data ghcr.io/piyushdoorwar/yamlet

Open it in your browser

Go to http://localhost:7878. Create a collection or import one you already have, then start sending requests. Use your browser's Install app option to give Yamlet its own window.

Commit your workspace

Everything lands in collections/, environments/ and globals/ as plain YAML. Review it, diff it, branch it and merge it like the rest of your code.

Updating

Remove the container and run the same command again; --pull always fetches the newest image. Your YAML lives in your folder, and keeping the same yamlet-data volume keeps the Chrome extension paired.

$ docker rm -f yamlet
$ docker run -d --pull always --name yamlet -p 127.0.0.1:7878:7878 -v .:/workspace -v yamlet-data:/data ghcr.io/piyushdoorwar/yamlet

Calling APIs on your machine

Inside the container, localhost is the container itself. Reach your machine in one of two ways:

  1. Use the host address http://host.docker.internal:<port> On Linux, also add --add-host=host.docker.internal:host-gateway
  2. Share the host network --network host -e HOST=127.0.0.1 Keep the HOST setting so Yamlet is not exposed to your network.
Features

Everything you expect from an API client, stored as files.

A full request workflow in the browser, with nothing hidden in a database or a hosted account.

One YAML file per request

Collections, folders and requests each live in their own small file, so diffs stay readable and merge conflicts stay rare.

Environments and variables

Request, collection, environment and global scopes. {{variables}} are highlighted inline; hover to peek a value, click to edit it.

Dynamic variables

Fresh test data on every send with {{$guid}}, {{$timestamp}}, {{$randomEmail}} and many more, with autocomplete as you type.

Scripts and tests

Pre-request and post-response JavaScript at request and collection level, with a pm API for variables, requests and pm.test assertions.

Auth, including OAuth 2.0

Bearer, Basic, API key and cookie auth, plus OAuth 2.0 client credentials, password and authorization code with PKCE. Inherit it from the collection.

Every method and body type

Every method including the new QUERY, or any custom verb. JSON, XML and text, multipart form-data with file fields, URL-encoded forms, GraphQL and binary uploads.

Collection runner

Run a collection or folder in order, repeat it for several iterations and feed it rows from a CSV or JSON data file.

Bring what you have

Import cURL commands, OpenAPI and Swagger specs, and v2.1 collection JSON exports. They are converted to Yamlet YAML on save.

Code snippets

Turn any request into ready-to-paste code for cURL, JavaScript, Python, Go, C#, Java and other languages.

Cookie manager

See, edit and clear the cookies your requests collect, per domain, without leaving the app. The optional Yamlet Interceptor Chrome extension syncs cookies from sites you approve.

Examples and history

Save responses as examples next to the request, and revisit what you sent earlier from the request history.

Tabs and shortcuts

Work across many requests in tabs that come back when you return, and keep your hands on the keyboard with shortcuts, including Ctrl+K to jump to any request.

Use your browser's cookies in Yamlet.

The free Yamlet Interceptor extension syncs cookies from the sites you approve into the Yamlet running on your computer. Pair it in one click from Yamlet's Cookies dialog.

Git-friendly by design

Your workspace is just a folder.

No export step and no sync service. The files Yamlet writes are the source of truth, so code review works on API changes the same way it works on code.

  • A request is self-contained: method, URL, headers, body, auth, scripts and its order in the tree.
  • Small, stable files mean a change to one request touches one file.
  • Keep secrets out of Git by leaving them in a local environment file.

Command line

Run the same collections in CI.

The yamlet CLI (@piyushdoorwar/yamlet on npm) runs a workspace headlessly: every request, every script, every pm.test. It prints a results table and exits with code 1 if anything fails. 

$ npm install -g @piyushdoorwar/yamlet
$ yamlet run ./my-workspace --env dev
# or without installing
$ npx @piyushdoorwar/yamlet run ./my-workspace --reporter junit
--env dev--bail--iterations 5--data users.csv--reporter junit
